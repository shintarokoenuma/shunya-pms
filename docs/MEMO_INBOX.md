### M-007 ★価格と納期の用語定義 ― 「卸値」という概念は無い（慎太郎さん 2026-09-10）
- 記入: 2026-09-10 18時台 JST
- 状態: 起票済み(B-172 仕様確認書 v1.0 の D-0・commit 3036132)／★仕様書 Part4 第12部の用語集への反映は未
- 経緯: M-004 / M-006 で Claude が「売値」「卸値」を混在させて書いていたため、定義を確認した回答。

#### 原文（慎太郎さん 2026-09-10）
> 卸値と売値の定義を確認です。
> クライアントへ販売する量産価格＝売値、コスト、量産実績原価（発注後・材料費＋工賃）です。
> ※サンプルもほぼ同意。
> 弊社ではクライアントの上代に関与しません。その為、卸値という概念はありません。
> 納期＝弊社がクライアントに約束した納期を提示してオーダーをもらう。
> 発注締日も明記必要。

#### 確定した用語（★以後この語だけを使う）
| 語 | 定義 | 社外に出すか |
|---|---|---|
| **売値** | クライアントへ販売する量産価格 | ★**出す**（先方ページに表示） |
| **コスト／量産実績原価** | 発注後の 材料費＋工賃 | ★**出さない** |
| **納期** | ★**弊社がクライアントに約束した納期**。これを提示してオーダーをもらう | ★**出す** |
| **発注締日** | ★オーダーの締切日。**明記が必要** | ★**出す** |
| ~~卸値~~ | ★**使わない。** shunya はクライアントの上代に関与しないため、卸値という概念が存在しない | — |

- ★サンプルも**ほぼ同じ構造**（サンプル価格＝売値、サンプルのコスト＝実績原価）。
- ★**過去の記述で「卸値」を使っている箇所は語の誤り**である（M-002 の4、BACKLOG B-171 / B-172 の定義欄）。
  BACKLOG の既存定義文は書き換えず、追記で訂正する運用にした（commit 3036132）。

#### ★この定義が変えたこと
1. D-5（社外に見せるもの）に **発注締日**が加わり、計8項目になった
   （先方品番・絵型・色・サイズ・数量・売値・納期・発注締日）。
2. 「表示納期と実納期は異なる」（M-002 の5）の意味が明確になった。
   **表示納期＝約束納期**（対外的なコミット）であり、嘘の納期ではない。社内の実納期（実際の進行）と別に持つ、という話。
3. 「卸値」で書かれた過去の記述は、すべて「売値」に読み替える。
4. ★2026-09-20（M-016 の12）: **約束納期はクライアント向け。工場に渡す帳票には出さない**（工場には工場ごとの希望納期のみ）。

### M-015 ★パターン番号はサンプルナンバーに1つ・2nd／グレーディング／量産／リピートでも変わらない。どの型紙で作ったかを日付で見える化したい（慎太郎さん 2026-09-19〜20）
- 記入: 2026-09-19 09時台 JST（2つ目の回答は 2026-09-20 追記）
- 状態: 未起票（B-146 / B-054 の仕様確認書 v0.1 に反映する）
- 経緯: M-013 の続き。「パターン番号は1つの型番に1つか、修正で変わるか」「リピートで引き継ぐか」を質問した回答。

#### 原文（慎太郎さん 2026-09-19）
> １つのサンプルナンバーに対してサンプルパターンが付与されます。
> 2nd作成の際にパターンが変わることやグレーディングが増えることがありますが番号は変更ありません。
> 量産時に最終の修正やグレーディングを行います。こちらでも番号の変更はありません。
> しかし、どのパターンで作成しているのかをみえるかしたいので、日付を持っていることが重要になると思います。

#### 原文（慎太郎さん 2026-09-20）
> リピートのパターン品番は同品番を使用。

#### 確定
1. ★**パターン番号は「サンプルナンバー」1つに対して1つ付与される。**
2. ★**番号は変わらない**: 2nd サンプルで型紙が変わっても、グレーディングが増えても、量産時の最終修正・グレーディングでも同じ番号。
3. ★**リピートでも同じパターン番号を使う**（2026-09-20）。
4. ★**型紙の中身の変化は日付で持つ。** 目的は「**どの型紙（どの時点のもの）で作成しているのかを見える化する**」こと。

#### こちらの解釈（★原文と分けて書く）
- 1つの番号の下に、修正・グレーディングの**履歴（日付つき）**が積み重なる構造。リピート品番もその番号と履歴を共有する。
- ★リピートで引き継ぐため、番号の置き場所は**型番（ModelCode）側**が素直（ModelCode は「リピート系譜」の単位として設計されている・products[] を持つ）。品番側に置くとリピートのたびに写す必要がある。
- 既存の器との対応（★未検証を含む）:
  - `PatternVersion`（modelCodeId に紐づく）の1行＝型紙の1回の受領（新規／修正／グレーディング）。`receivedAt`（受領日）・`workType`（コメント上は 新規/修正/グレーディング・enum 値は未実測）・`hasGrading` / `gradingSizes` が既存
  - 「どの型紙で作ったか」＝サンプル製作と WO が `patternVersionId` を持っている可能性（`sample-productions.ts:600` / `work-orders.ts:854` が値を受け渡している＝列の実在は未実測）
  - 番号（16sy-082）を入れる列は ModelCode にも無い（2026-09-19 実測の全文に該当列なし）。★置く場合は ADD COLUMN（nullable・非破壊）が1本要る見込み

#### ★未確定（次に確認する）
- ★「サンプルナンバー」がシステムのどの番号に当たるか。2nd でも番号が変わらないので、ラウンドごとに採番される SP 番号（SP-2026-0042）ではなく、**品番（社内品番）**と読んでいる（未確認・訂正の申し出はまだ無い）

### M-019 ★絵型を PDF に載せる方式は「Buffer で読み、sharp で JPEG に正規化」― 署名URL方式は使えない（2026-09-21 実測）

### M-003 原価計算の方向 ― 総額÷数量 か、1枚から積み上げるか（確認済み・変更不要）
- 記入: 2026-09-08（保存は 2026-09-10 01:58 JST・2日越しになった。理由は下記★。★初稿は date を取らずに「2026-09-09」と書いており、それ自体が日付を測らずに書く再発だった）
- 状態: 見送り（既に確定済みのため新規起票しない）

#### 原文（慎太郎さん 2026-09-08）
> 原価計算の方法が、材料合計を数量で割り返す方法をとってるけど、逆にする方がいいのでは？
> という議論を過去にした気がするんだけど、一度確認してください。

#### 確認結果（claude.ai 側で project knowledge の spec 原文を検索して確認）
1. **過去に議論して確定済み。** qe-1-spec-confirmation-v1_0-2026-06-30.md §3-3（Q-a 確定）:
   1枚原価 =（材料費Σ + 工賃Σ）÷ Σ(productionQuantity)。
   「割戻し分母 = Σ(productionQuantity) で確定」。理由は #93（資材所要量）と分母を揃えるため。
2. ★**逆にできない構造的な理由は同 §4 にある。** ROLL（反売り・取り切り）は
   反数 = ceil(必要量 ÷ Material.rollLength)、生地コスト = 反数 × Material.rollPrice。
   **ceil があるため生地コストは数量に対して非線形**で、「1枚あたり × 枚数 = 総額」が成立しない。
   500枚で3反・501枚で4反、という飛びが出る。少量ほどズレが大きい。
3. ★**工賃側も同型。** qe-1-spec-addendum-v0_1-2026-07-12.md §3 で、
   billingClassification = INDIVIDUAL_BILLING（版代・型代・パターン代）は**総額固定の費用**のため
   1枚原価の分子から外し別枠にする、と確定済み。固定費は枚数で割るしかない。
4. METER（メーター売り）の行は 必要量 × 単価 で線形なので1枚積み上げでも一致するが、
   ROLL と混在するため全体は割り返しに揃える（§3-3 の結論）。

#### ★「1枚単価から積み上げる」方式は別レイヤーで既に実装済み
qe1r-road-a-implementation-brief-2026-07-06.md §5-3:
> 総額はすべて導出（金額＝単価×数量・総合計＝製品合計＋初期費用合計）。電卓で合う。

つまり設計は二層になっている。
- 原価（社内）: 総額 → ÷数量 → 1枚原価。理由は反の切り上げと固定費が非線形だから
- 提示（客向け）: 1枚単価 → ×数量 → 総額。理由は先方が電卓で検算できる必要があるから

「逆にする」という発想自体は正しく、それは既に提示側で採用されている。原価側は逆にできない。

★2026-09-10 追記: **M-006 / M-007 はこの二層構造の上に載る話**である。
先方ページの**売値**＝提示側（1枚単価）、最終請求＝**コスト（量産実績原価）**側。
