## 原価計算（QE-1 / 品番カルテ）

### M-003 原価計算の方向 ― 総額÷数量 か、1枚から積み上げるか（確認済み・変更不要）
- 記入: 2026-09-08（保存は 2026-09-10 01:58 JST・2日越しになった。理由は下記★。★初稿は date を取らずに「2026-09-09」と書いており、それ自体が日付を測らずに書く再発だった）
- 状態: 見送り（既に確定済みのため新規起票しない）

#### 原文（慎太郎さん 2026-09-08）
> 原価計算の方法が、材料合計を数量で割り返す方法をとってるけど、逆にする方がいいのでは？
> という議論を過去にした気がするんだけど、一度確認してください。

#### 確認結果（claude.ai 側で project knowledge の spec 原文を検索して確認）
1. **過去に議論して確定済み。** qe-1-spec-confirmation-v1_0-2026-06-30.md §3-3（Q-a 確定）:
   1枚原価 =（材料費Σ + 工賃Σ）÷ Σ(productionQuantity)。
   「割戻し分母 = Σ(productionQuantity) で確定」。理由は #93（資材所要量）と分母を揃えるため。
2. ★**逆にできない構造的な理由は同 §4 にある。** ROLL（反売り・取り切り）は
   反数 = ceil(必要量 ÷ Material.rollLength)、生地コスト = 反数 × Material.rollPrice。
   **ceil があるため生地コストは数量に対して非線形**で、「1枚あたり × 枚数 = 総額」が成立しない。
   500枚で3反・501枚で4反、という飛びが出る。少量ほどズレが大きい。
3. ★**工賃側も同型。** qe-1-spec-addendum-v0_1-2026-07-12.md §3 で、
   billingClassification = INDIVIDUAL_BILLING（版代・型代・パターン代）は**総額固定の費用**のため
   1枚原価の分子から外し別枠にする、と確定済み。固定費は枚数で割るしかない。
4. METER（メーター売り）の行は 必要量 × 単価 で線形なので1枚積み上げでも一致するが、
   ROLL と混在するため全体は割り返しに揃える（§3-3 の結論）。

#### ★「1枚単価から積み上げる」方式は別レイヤーで既に実装済み
qe1r-road-a-implementation-brief-2026-07-06.md §5-3:
> 総額はすべて導出（金額＝単価×数量・総合計＝製品合計＋初期費用合計）。電卓で合う。

つまり設計は二層になっている。
- 原価（社内）: 総額 → ÷数量 → 1枚原価。理由は反の切り上げと固定費が非線形だから
- 提示（客向け）: 1枚単価 → ×数量 → 総額。理由は先方が電卓で検算できる必要があるから

「逆にする」という発想自体は正しく、それは既に提示側で採用されている。原価側は逆にできない。

#### 未確認（着手時に実測すること）
- src/lib/calc/production-cost.ts / material-requirement.ts の**現物は未読**。
  spec と実装が食い違う例は実在する（color-master-spec §5 と BomItemColorway・2026-09-07 実測）。
  実装が本当に ROLL の ceil を通しているかは read-only で確認する。

#### 残っている可能性のある別論点（次に話す時に確認する）
- 「数量が変わるたびに1枚原価が動くのが扱いにくい」なら、それは上の議論とは別の話
- 「BOM 側に1枚あたりの単価を持ちたい」なら、それも別の論点

#### ★保存が1日遅れた理由（記録）
慎太郎さんの質問に回答したあと、Claude が「M-003 として保存しますか」と聞いて返事を待った。
memo-inbox スキルは「受け取ったターンの中で保存する」と定めており、聞かずに保存すべきだった。

#### 確定
1. ★**1枚目＝縫製工場用**: 絵型（大）・付属・数量・仕様を1枚で分かるように。
2. ★**2枚目＝採寸用**: 絵型（小）・サイズ・数量・仕様。★**宛先は工場か検品所**。
3. ★**3枚目＝加工工場用**: 絵型（大）・加工指示書。加工は絵型での指示が多いので**画像の追加**で載せる。
4. ★**2枚目のサイズ＝仕上がり寸法表**。★**縫い上がり寸と加工後の上がり寸の2列を常に出す**。
   ★**寸法はエクセルの仕様書から読み込めるとよい。メールからの読み込みもできれば尚よい**（→ B-056 / B-206）。
5. ★**共通帯（品番・パターン番号と型紙の日付）は3枚とも同じでよい。** ★ただし約束納期は帯から外す（12）。
6. ★**絵型の画像は横型で使いたい。**
7. ★**1枚目は1枚に収めたい。** ★付属は**多くても 10〜15 品番程度**。**その分、絵型を大きくする。**
8. ★**カラーは多くても5色程度。**
9. ★**用紙は B4。**
10. ★**文字をもう少し見やすく（大きく）。**
11. ★**追加で明記する項目**: 工場名・先方担当者・弊社の情報・弊社担当者・日付・職出し予定日・希望納期。
    ★**工場名・先方担当者・職出し予定日・希望納期は「工場ごとに必要」**＝ページ（渡す工場）ごとに宛先が変わる。
12. ★**工場に渡す帳票には「希望納期」だけを載せる。** クライアントへの約束納期（M-007）は載せない。
13. ★**納期は工場ごとに異なる。工場ごとの納期を入力する場所が無いと思う**（慎太郎さんの認識）。
    → ★**2026-09-20 実測で「希望納期」の入力欄は既に存在**（`work-order-form.tsx:574`）。追加実装は不要。
14. ★**加工工場が複数ある品番は、3枚目を加工工場ごとに1枚ずつ出す**。
15. ★**量産・サンプルの両方に同じ帳票を使い、どちらかが分かるように明記する**（区分の札）。
16. ★**区分の札の表示名**: やり直し＝「量産（やり直し）」、追加発注＝「量産（追加）」。
17. ★**今後は品番とパターン番号を同じ番号にしていく。先方支給のパターンは先方が確定するので変えられない。**
18. ★**「ご担当」は宛先の工場の主担当1人**で足りる。
19. ★**「職出し予定日」＝資材・型紙を揃えて工場に作業を出す予定の日**（WO の `plannedStartDate`）。
20. ★**クライアント品番（先方品番）も載せる**。下げ札などの紐付けに要る。
21. ★**宛先は発注（WO）がある工場だけ**（初版）。★ただし相見積もり・発注前の見積依頼で送る可能性はある → 初版のスコープ外（受け先 B-135 / B-174）。
