## 3. 確定した設計（要点・原文はブリーフ）

- 器は **PeriodClose（period_closes）＋ PeriodCloseStatus（CLOSED / REOPENED）**。1回の締め＝1行。解除は同じ行を REOPENED にして解除した人・日時・理由を残す。締め直しは新しい行（P6-D1）
- 取引先の種類は既存の CounterpartType（CLIENT / SUPPLIER / FACTORY / CONTRACTOR）。期間は行に保存し、あとで締め日を変えても締めた行は動かない（P6-D3）
- 判定は `src/lib/period-close/lock.ts` の checkPeriodLock の1つだけ。サーバが正で、画面（帯・ボタンの無効化）は案内
- 止めるもの: 納品書（deliveryDate）・請求書（periodEndDate）・入金（actualPaymentDate ?? scheduledDate）・PO / WO（orderDate）の作成・編集・削除・状態の変更。**PO / WO は CANCELLED への変更だけを止め、進捗の状態は変えられる**（P6-D8）
- 量産発注の生成は、PO / WO を1件も作る前に、すべての相手先を今日（JST）で判定する（production-order-generation.ts:344）。PO / WO を作る処理の中でも、もう一度判定する
- 締めは社内の誰でもできる。解除は OWNER / ADMIN だけ（role を変える画面は無い・B-205）
- 処理が済んでいない伝票が残っていても、警告して締められる（closeWarnings に保存）。警告は確認ダイアログを開くたびに数え直す（v1.1）
- 重なる期間: 一覧ではその月を「締め中」（締め中の期間も表示）として、締めるボタンを出さない。サーバでも closePeriod が止める（P6-D5）
- 請求書の運用は「送付済みにしてから、その月を締める」（P6-D13）
- nav: 取引から請求・入金を外し、「経理」（請求・入金・締め）を新しく作った（案B）
- AuditLog: 締め＝CREATE、解除＝UPDATE（entityType "PeriodClose"・理由つき）
- B-235: 締め日・支払日の入力欄を、type=number のまま文字列で持つようにした。15 など任意の日を手で打てる（クライアント・仕入先・工場・外注先の4フォーム）
