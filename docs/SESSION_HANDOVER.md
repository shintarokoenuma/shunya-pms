## ⑧ このセッションの失敗と対策

★1〜3は claude.ai 側（指示を書く側）の誤りで、Claude Code が正しく止めて回避した。

1. ★部分編集の停止条件に「git diff -U0 の hunk 数が 1」と書き、正しい作業が STOP した（実測3）。
   -U0 は変更行の間に未変更行が挟まると hunk を分割する。文脈つき diff では1つの @@ に収まっていた。
   → **-U0 の hunk 数を停止条件に使わない**
2. ★Edit の old_string を、プロジェクトナレッジ側の文言から書き写して渡した。repo の同じ行は
   backtick と補足が無く一致しなかった。Claude Code が現物を grep して当て直した。
   → **old_string は repo の現物から取る**
3. ★repo とナレッジが12バイトずれていた（改訂履歴の見出しが「バージョン」/「版」）。
   チェックサムで突き合わせて初めて判明した。
   → **同じ文書が2箇所にあるとき、同一だと仮定しない。shasum -a 256 と wc -c で照合してから
     「同期済み」と書く**

4. ★★**同じ穴が Claude Code 側にも空いている（2026-09-06・この締めで発生）。**
   締めの保存ブロックに対し Claude Code が実行前に停止し、「スキル修正・SHA照合・ナレッジ検索は
   この会話で起きていない＝虚偽記載」と判定した。実際はすべて claude.ai 側のツール実行で、
   raw 出力はそちらのチャットに残っている。Claude Code からはスキル本体もナレッジも見えないだけである。
   - ★**「自分の会話に見えない」を「起きていない」の根拠にしない。** 書けるのは
     「この会話には見えない」までである（file-write-verification 鉄則8 の鏡像）
   - ★停止して確認したこと自体は正しい。**誤っていたのは断定の強さ**である
   - ★claude.ai 側は、Claude Code に見えない作業をメモに書くとき、
