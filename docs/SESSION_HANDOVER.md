## ⑨ このセッションの失敗と対策

1. ★モデル名を推量で grep した。自社カラーマスターを ColorMaster と当てて grep し、
   空だったため「色マスターは存在しない」と読みかけた。正しくは model Color（colors）で、
   colors.ts に CRUD まである稼働中のマスターだった。
   → モデル名・列名は spec 原文か grep '^model ' で確定してから使う。
     空の grep 結果を「存在しない」の根拠にしない（shunya-design-reread に提案カードで反映）

2. ★同一の出力が3回貼られた（BLOCK-C の再掲が2回）。長いブロックが Claude Code に届かない事象。
   → 鉄則「受け取った出力が直前と同一なら分析しない」が3回とも機能し、事故は起きていない。
     抜け方は「貼り付けをやめて1行を直接打ってもらう」で、unzip -p の1行が通った。
   → ★今回から全ブロックに判別用マーカー行（BLOCK-A / RECON-B170 等）を入れた。
     これが有効だった。既存鉄則の運用として定着させる（スキルへの追加はしていない）

3. ★セッションが日をまたいだ（4回目）。冒頭の照合（9/6 日）は正しかったが、
   00:44 の recon で 9/7（月）になっていた。
   → 今回は recon の date で気づけた。★このメモの日付は 9/7 を使っている

4. ★Claude Code 側は今回、前メモ⑧-4 の轍を踏まなかった。「スキル本体はこの会話から見えない
   可能性が高い」とだけ書き、「起きていない」とは断定しなかった。反省が機能している。
   ただし claude.ai 側では実際に確認済みだったので、どちらで実行したかを1行添える運用は継続する。
