## 0. 結論（先に4行）

1. 背骨（品番カルテを根とする動線）は src/lib/nav/breadcrumb.ts に純関数としてコード化されているが、
   画面内の明示リンクは背骨に従っていない

## 4. 動線の実測 — 背骨と欠落

### 4-1. 背骨はコード化されている

src/lib/nav/breadcrumb.ts の buildDocBreadcrumb は、伝票のパンくずを次の形で構築する:

    product あり: 品番カルテ(/products) › {品番}(/products/[id]) › [サンプル {番号}(/samples/[id]) ›] {現在}
    product なし: {一覧label} › {現在}（野良伝票の退化表示）

根は常に品番カルテ。これは product-sample v1.0 §4-1 の背骨がそのまま実装されたもの。
B-173 はこの背骨を全体図に広げる作業であり、背骨そのものを新たに決める作業ではない。

### 4-2. ★親へ戻るエッジの有無（確定・畳み込みの影響を受けない）

| 伝票 | → /products/[id] | → /samples/[id] |
|---|---|---|
| サンプル | あり | — |
| 量産見積（PE） | あり | 無し |
| 発注（仕入 PO） | 無し | あり |
| 発注（作業 WO） | 無し | あり |
| ★受注（SO） | 無し | 無し |
| ★納品（DLV） | 無し | 無し |

受注と納品は、送り元を丸ごと畳んでも品番・サンプルへ向かうエッジが 1 本も存在しない。
パンくずは breadcrumb.ts により表示されるが、画面内の明示リンクとしては背骨に接続していない。
→ B-182

PO / WO はサンプルへは戻れるが品番へは戻れない。サンプルに紐づかない量産発注では、
画面内の戻り先が消える（パンくずは product あり分岐で正しく出る）。B-182 に含める。

### 4-3. カルテがハブになっている

/products を送り元とするエッジ（一覧・詳細の区別は §1 の限界により不可）:

    /products -> /products/[id] / /products/new
    /products -> /production-estimates/[id] / [id]/edit / [id]/generate
    /products -> /sales-orders/[id] / /sales-orders/new
    /products -> /work-orders/[id]
    /products -> /product-categories/[id]/edit
    /products/[id] -> /clients/[id] / /products/[id]/edit / /samples/new

案件から取引への分岐はすべてカルテを起点にしている。設計どおり。

### 4-4. ダッシュボードが袋小路

/login -> /dashboard のエッジはあるが、/dashboard を送り元とするエッジは 0 本。
ログイン直後に着地する画面から、業務画面へ進む導線が無い。→ B-183

### 4-5. 見積 2 系統の非対称

    /quotations -> /production-estimates/[id]   （出口はこの 1 本のみ）
    /quotations への入口: ナビのみ
    /production-estimates: 一覧ルートが存在しない

確定見積（Quotation）は一覧だけがあり詳細も新規も無い。量産見積（PE）は詳細だけがあり一覧が無い。
2 系統が 1 つのナビ項目を共有した結果、どちらも片肺になっている。B-144 の実害がこれ。

## 8. 起票を見送った観察と、その理由

- Inquiry がナビのマスター節にある（原設計ではステップ 1）
  → 画面が実装される時点で配置し直す話であり、今 B番号を振っても実装まで動かない。B-132 の中で扱う
- マスター 15 種の横串リンクが不均一（clients↔brands/buyers、materials→suppliers、
  delivery-destinations→buyers/clients のみ）
  → 業務上の必要が無いところに横串を足す理由が無い。実務で不足が出たら起票する
- /skus へのエッジ 0
  → ページ自体が無い（enabled:false）ため動線の問題ではない
