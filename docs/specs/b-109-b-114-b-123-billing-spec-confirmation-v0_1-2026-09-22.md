## 0. 結論（先に5行）

1. **合計請求書は、クライアントごと・締めの期間ごとに、その期間の納品書をサンプル・量産の区別なく合算して1枚にする**（慎太郎さん確定 2026-09-22）。
2. **請求の単価は「納品の時に直した売値」**。量産実績原価を根拠に売値を直し（B-201 の③）、その売値が納品書明細の単価になり、請求書はそれを写す。コストは社外に出さない。
3. **請求系の器（Invoice / InvoiceItem / Payment / InvoicePayment）は schema 完備・DB 適用済み・src 実使用ゼロ**。請求書のために migration は要らない見込み。
4. **量産の納品書を作る経路が無い**（delivery-notes.ts:465 が skuId: null 固定）。合計請求書に量産を載せるには、先に納品書側へ「受注（SKU）から引き当てる」経路を足す（B-114）。
5. 締め（B-123）は v1 では **「請求書を確定したら、その請求書に載った納品書・明細は二重に請求できない＋確定後の請求書は書き換えず取消→再発行」** までとし、PO/WO を含む期間ロックは後段に分ける案（Q-6）。

### 2-6. 追加 recon（2026-09-22 15:48 JST・read-only）

- **締め（期間ロック）専用の休眠モデルは無い**（model 名に period / close / lock / fiscal / ledger / settle / cutoff を含むもの 0件・全モデル名を目視）。→ 締めを記録する器は **新モデル（ADD TABLE・migration 1本）** になる見込み。締め・解除の履歴は AuditLog（action / entityType / entityId / beforeData / afterData / description）に残せる
- **Supplier / Factory / Contractor も Client と同じ取引条件の列を持つ**（taxId / isQualifiedInvoiceIssuer / paymentTermType / closingDay / paymentMonthOffset / paymentDay）。→ D-16 の「仕入先・工場ごとの締日」は既存列で足りる
- **PO/WO には status による編集・削除のガードが無い**（DRAFT は create 時の初期値のみ）。→ 月ごとのロック（D-13）を入れるとき、PO/WO の update / delete / status 変更の各 action にロック判定を足す

```
受注（SO・SKU×数量・単価）
```

## 4. 設計（たたき台）

### 4-1. 量産の納品書（B-114）

- 引き当てダイアログに **「受注（量産）」** の引き当て元を足す。受注（CONFIRMED 以降）を選ぶ → SKU（色×サイズ）ごとに「受注数・納品済み・残り」を出す → 今回の数を入れて追加。
- 追加された明細: `skuId` / `productId` / `soId` / `soItemId`（休眠列を起こす）/ colorName / size / quantity / `unitPrice` = **受注の単価を初期値にし、人が直す**（D-2）。
- ★量産の明細は **skuId 必須をアプリ側で担保**する（B-108 §3-1 の申し送り）。
- 表示は明細の行を並べるだけか、品番ごとに色×サイズのマトリクスにするかは Q-4（モックで決める）。
- 受注の納品済み数（`SoItem.deliveredQuantity` / `remainingQuantity`・`Sku.deliveredQuantity`）は、納品書を **納品完了（DELIVERED）にした時**に更新する（D-17）。

### 4-2. 売値を直す（D-1・D-2）

- 直す場所は **納品書明細の単価**。受注・量産見積の単価は書き換えない（受注時の約束と納品時の確定を両方残す）。
- 画面では、受注の単価と直した単価が違う行に印を出す（違うこと自体は正常）。
- ★稀に取引先ごとに違う決め方（D-1 の④）は v1 では **人が単価を入れることで吸収**する（計算の型は持たない）。

### 4-3. 合計請求書の作り方（B-109）

1. クライアントを選ぶ → 取引条件（paymentTermType）で締めの型が決まる。
   - MONTHLY_CLOSING … 締日（closingDay）で期間を切る（例: 31 = 前月末の翌日〜当月末）。
   - DEPOSIT_COD / ADVANCE_PAYMENT / CASH_ON_DELIVERY … **納品前に先の請求書を出す**（D-7）。デポジットは設定％、前払い・代引きは 100%。基準額と差額は Q-2a
   - LETTER_OF_CREDIT / CUSTOM … 今は使っていない（D-9）。v1 では請求書を作れない旨を画面に出す
2. 期間内の **納品完了（DELIVERED）以降の納品書**（D-6）の明細のうち、まだどの請求書にも載っていないものを並べる。サンプル・量産の区別はしない（D-4）。
3. 人が確認して（外す行は外せる）保存 → `INV-{年}-{4桁}` を採番（DLV と同型・論理削除も母数に含める）。
4. 請求書の明細は納品書明細の **スナップショット**（品名・先方品番・色・サイズ・数量・単価）。`deliveryNoteItemId` で元を辿れる。
5. 支払期日 = 締日と取引条件（paymentMonthOffset / paymentDay）から自動計算し、人が直せる。
6. 請求先 = `Client.billing*` → `Client` 基本（B-108 §4-2 の連鎖・スナップショット）。

### 4-4. 二重請求の防止

- 1つの納品書明細は、**取消されていない請求書に1回だけ**載る。候補から除外し、保存時にもサーバ側で確かめる。
- 納品書明細の id は、発行後は編集されないので安定している（B-124 の「編集で作り直し」は DRAFT のみの話）。

### 4-5. 消費税（インボイス制度）

- 明細ごとに税率・税区分を持つ（国内 10% = STANDARD_10 を既定・輸出は EXEMPT）。
- **消費税額の端数処理は、請求書1枚につき税率ごとに1回**（インボイス制度の要件）。処理の向き（切り捨て／四捨五入／切り上げ）は Q-3。
- 請求書に載せる必須項目: 発行者名・登録番号（T2011001051698）・取引年月日・内容・税率ごとの合計と税額・請求先名。

### 4-6. 請求書の状態（v1 で使う値）

- DRAFT（作成中・編集可）→ SENT（送付済み＝確定・以後は書き換えない）→ PAID / PARTIALLY_PAID（入金は Q-7）／CANCELLED（取消）。
- 承認フロー（PENDING_APPROVAL / APPROVED）・ACKNOWLEDGED・OVERDUE（自動判定）・REFUNDED・WRITTEN_OFF は v1 では出さない。enum は変更しない。

### 4-7. 締め・訂正（B-123 の v1 範囲・Q-6）

- 確定（SENT）した請求書は書き換えない。誤りは **取消（CANCELLED）→ 正しい請求書を新しい番号で再発行**し、再発行側に元の請求書への参照を持たせる（インボイス制度の修正インボイス＝「当初交付分との関連性を明らかにして交付」）。
- 取消した請求書に載っていた納品書明細は、再び請求の候補に戻る。
- 元請求書への参照列は Invoice に無い（持つなら ADD COLUMN 1本・休眠列の有無を先に当たる）。
- ★**月ごとのロック（D-13）**: 締めた月（計上日で判定）の納品書・PO/WO の編集・取消・削除を、UI とサーバの両方で止める。締めの解除は記録を残す（誰が・いつ・理由）。締め後の変更の証跡（B-123 ノート §2 の3）の出し方は v1.0 で決める。
  - 計上日: 納品書 = deliveryDate（確定済み）。PO/WO = orderDate（発注日・D-14）。
  - ★締めを記録する器は **schema の休眠モデルを一覧で当たってから**決める（PeriodClose / ClosingPeriod / AccountingPeriod 等を名前で推量しない）。無ければ新モデル（ADD TABLE・migration 1本）。
  - ★PO/WO の現状の編集可能範囲（B-123 ノート §4 の3）は未確認。着手前に実測する。

### 4-8. 自社の登録番号の置き場所

- `COMPANY_PROFILE` 定数に登録番号を足し、請求書を作るときに `Invoice.issuerTaxId` / issuerName / issuerAddress へ **スナップショット**する（他の帳票と同じ出所・発行後に定数が変わっても発行済みは変わらない）。
- Company テーブルへの移行（設定画面化）は既存の申し送り（company-profile.ts 冒頭コメント）どおり別タスク。

### 4-9. PDF

- 請求書 PDF を新設（B-086 のプレビュー → 承認後ダウンロード方式・react-pdf・A4 縦の見込み）。
- 納品書 PDF（B-108 PR3）も同時に作る（D-12）。発行者ブロック・宛先・明細の形を2帳票でそろえる。

### 4-10. 画面

- サイドバー「取引」に **請求（INV）** を足す（nav-items.ts:80-81 のコメントどおり）。一覧・新規（クライアントと期間を選ぶ → 候補の明細 → 確認 → 保存）・詳細（送付済みにする・取消・PDF）。
- ★画面の並べ方は参考のモックを作って決める（Q-4 と一緒に）。
