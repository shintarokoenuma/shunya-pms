## 0. 対象の確定と系譜

### 0-1. 名称の系譜整理（正名化）
qe-1 v1.0 の自己定義は「量産見積の計算」だったが、PR #101 マージ時に実体に合わせ
**「量産実績原価（発注後・材料費＋工賃）」**へ正名化された。本書はこの空いた「量産見積」の
座席を (A) として正式に引き取る。以後の呼称:
- **QE-1R** ＝ 概算量産見積（交渉前・経験値/他品番実績・独立レーン）
- **(A) 量産見積** ＝ サンプル後またはリピートの、受注前1枚単価提示（本書）
- **QE-1（量産実績原価）** ＝ 発注後の実績集計ビュー（PR #101・クローズ済み）

### 0-2. QE-1R との排他基準（振り分けの一問）
**「この数字の根拠は、この品番自身の実績か？」**
- Yes（確定サンプル実績／過去量産実績）→ (A)
- No（経験値・他品番からの類推）→ QE-1R
サンプルの有無は結果であって基準ではない。QE-1R で概算を先に出す運用は残る（排他は
「正式な量産見積は (A) から出す」の一点のみ）。QE-1R v0.1 §1 の独立レーン確定は不変。

### 0-3. 業務フロー上の位置
概算見積(QE-1R) → サンプル → **量産見積(A)** → 受注 → **量産発注生成(B)** → 生産 →
**事後確認(C)=実績原価との突合**。1枚単価が要るのは (A) 時点。(C) は請求突合・原価率検証用。

## 1. (A) 量産見積レーン

### 1-1. 性格（確定）
- **保存型・提示価格込み**。発行履歴として保存する（いつ・いくら・どの条件で出したか）。
- 作法は QE-1R の house style を踏襲: 機械が既定値を入れ、人が最後に上書きして整える。
  自動計算値と手打ち最終値は別列で両方保存（手打ちで自動値を潰さない）。
- 手打ちの粒度は QE-1R addendum v0.2 と同じ: **(a) 1枚単価 (b) 初期費用の項目別提示額**。
  総額は導出値。
- 利益率: 1件1率・Brand.defaultMarginRate 既定・変更可（QE-1R §5-1 と同一）。

### 1-2. seed 2種構造（確定）
見積の実体（明細行の集合＋微調整＋提示価格）と計算エンジンは seed 非依存の1本。
入口の取り込みだけが2種類:
- **seed①: 確定サンプル実績コピー**（先行実装）。新規案件の標準ルート。
  当該品番の確定サンプル(§1-3)に紐づく PO/WO 明細をスナップショットコピー。
  単価の実在性と付属の網羅性（BOM 未登載の下げ札・ポリ袋等もサンプル PO に実在）が根拠。
- **seed②: BOM＋過去量産実績**（第2段）。リピート再見積（サンプル無し）で機能。
  BOM は発注後に整うため新規では機能しづらいが、量産済み品番では最良の source になる。
- 行単位の source は enum で記録（QE-1R 論点3と同 house style。値の詳細は実装ブリーフ段）。
  行単位の混在（生地は BOM・付属はサンプル）も構造上許容。

### 1-3. 確定サンプル指定（Q-a 確定）
- コピー元は「品番のサンプル全部」ではなく**確定サンプル1点**に絞る（複数ラウンドの
  失敗発注・トワル生地等の混入を構造で防ぐ）。
- **新設フラグ（量産見積基準の指定・1品番1点制約）で確定**。既存 isApproved /
  clientApproved は「承認」の事実記録であり「量産見積の基準にする」とは意味が別
  （承認ラウンド複数・客先/社内のずれ）。status = APPROVED のラウンドを既定候補として
  UI 提示する。列名・制約の実装は実装ブリーフ段。
- 導線は実在: SampleProduction.patternWoId / sewingWoId（直結）＋
  PurchaseOrder.sampleProductionId ＋ WorkOrder.samplProductionId 経由で発注群を特定。

### 1-4. 単価と量の source 分離（確定・生地行の中核）
- **単価** ＝ seed のコピー値（サンプル実績 or BOM/過去実績）。
- **量** ＝ 用尺 × 量産数 × (1＋ロス率)。サンプル PO の生地数量から量産用尺は逆算不能
  （サンプルは裁断効率が悪い）ため、用尺は BOM に値があれば既定値・無ければ手入力。
- 取り切り(ROLL)/METER 分岐・カット代(METER のみ・行通貨)・混在通貨換算(JPY/USD・
  手入力レート・CNY/VND/EUR 除外)は qe-1 v1.0 §4-§5＋addendum §2 を全面適用し、
  計算コアは src/lib/calc/production-cost.ts（@prisma 非依存の純関数）を流用する。
- 付属・工賃行は単価コピー＋数量再計算のみ。工賃はサンプル単価≠量産単価が常態のため、
  微調整レイヤーの主戦場と位置づける。

### 1-5. 絶対防衛線の貫通（確定）
- seed①コピー時、billingClassification = INDIVIDUAL_BILLING の行（パターン代・版代等）は
  **1枚単価の行として取り込まない**。別枠「別途請求項目（1枚原価外）」への転記候補として
  参考表示し、既定は非計上（量産で再請求するかは案件次第・人が明示的に計上へ切替）。
- 1枚原価の分子に初期費用を混ぜない防衛線は (A)(B)(C) 全段で不変。

### 1-6. 通貨の注意（現物発見の反映）
- T-0 修正前に保存された既存サンプル WO/PO 明細の currency 値は信用しない
  （@default(JPY) 固定で記録されている）。コピー時は通貨を微調整レイヤーで必ず人が
  確認・修正できる UI とする。

### 1-7. 保存箱（Q-b 確定）
- **軽量新設（仮称 ProductionEstimate ＋ 明細 ProductionEstimateItem）で確定**。
  RoughEstimate への相乗りは概算と正式見積の混在を生み、QE-1R v0.1 §3 が Quotation
  相乗りを退けたのと同じ轍を踏むため不採用。
- 列語彙は RoughEstimate/Item と揃える（finalUnitPriceManualJpy・marginRate・
  isSeparateBilling・source 等の house style 踏襲）。列定義は実装ブリーフ段。
- 新設は **migration＝本番スキーマ変更を伴う**。triple-gate（dev 確認 → 本番 dry-run
  ROLLBACK＋件数確認 → 本番 commit）対象。

### 1-8. 見積数量＝分母（Q-c 確定）
- **手入力とし、Σ(Sku.productionQuantity) を既定値として提示**。見積時点は受注前で
  SKU 数量が仮のことがあるため、SKU への固定参照にしない（保存時は入力値を焼き込む）。

## 2. (B) 量産発注生成

### 2-1. 原則（確定）
- **「サンプル＝順方向入力・量産＝逆方向生成」**。SKU 量産数を注ぐと、仕入先別 PO・
  工場別 WO の**下書き（DRAFT）**が生成される。
- 量産製作セット（SampleProduction の量産版モデル）は**新設しない**。
  WorkOrderCategory = PRODUCTION タグ＋生成パイプラインで表現する。
- **初期費用は生成時にコピーしない**（確定）。版・型は再利用が既定であり、再製版は
  人が明示的に起票する。
- 生成物は下書きであり人が確定前に編集する（WorkOrder の DRAFT 編集可否＝既存
  open question「B: status = DRAFT なら編集可」を本実装で解消する）。

### 2-2. 業務ルールの正式収載（確定）
**量産 WO の工程明細（縫製・加工・仕上げ）の数量は、品番の量産数（Σ SKU.productionQuantity）
と一致する。** 不一致は品番を分けるべき案件＝見積として不成立。生成パイプラインは
この一致を保証し、以後の編集にも整合チェックを掛ける（チェック実装の段は実装ブリーフで）。

### 2-3. 生成の種（Q-d 確定）
- **(A) の保存済み量産見積（最新版）を種に生成する**。見積→発注の一気通貫が
  「逆方向生成」の実体（見積行の仕入先/工場・単価・通貨が下書きの初期値になる）。
- 見積が無い品番での直接生成（seed 相当の直接入力）を許すかは実装ブリーフ段で判断。

### 2-4. 前提タスク
T-0（WoItem/PoItem 行通貨保存修正）の完了を (B) 実装の前提とする。

### 2-5. B-065 の吸収（Q-e 確定）
- **本書に吸収する**。(B) の PO 生成明細はカラーウェイ×サイズ粒度が自然であり、
  PO 作成フォームへの colorway select（PoItem.productColorwayId 新設）を (B) の一部として
  実装する。**PR #94 はクローズ**（inverted subject-object 実装は破棄・正方向は
  「PoItem が productColorwayId を持つ」）。

## 3. (C) 事後確認（方向性のみ・実装は (A)(B) の後）

- PR #101（量産実績原価）の材料費側は現状 BOM×単価の理論値。ここに
  **品番直結 PO の実額合計**を追加し、「BOM 理論値 vs 発注実額」を並置する。
  見積とのずれ・ロスの実態が数字で見え、原価率確認が自動化される。
- 反の複数品番跨ぎの按分は**当面手動**（慎太郎さん確定 2026-07-16）。
  PoAllocation（schema 実在）による按分実装は次フェーズ（B-073）。
  v1 は productId 直結 PO のみ合計。
- 本書では方向性の明記に留める。
