## 5. 権限と判定

### 5-1. 変更できる人

- オーナー・管理者（OWNER / ADMIN）。既存の判定2か所（`ui-preferences.ts:21-24` の `canManageCompanySettings(role: string…)`・`period-close/lock.ts:40-43` の `canReopenPeriod(role: UserRole…)`）を1つの関数にまとめ、引数の型をそろえる
- ★画面で隠すだけでなく、action 側でも同じ判定で拒否する
- ★最後のオーナーの役割変更・停止・アーカイブは拒否する。自分の役割は自分で変えられない（D-17）

### 5-2. 見るだけ・隠す

- オーナー・管理者以外は、既定で入力欄・保存・招待・停止・アーカイブ・役割の変更を出さない
- 「見るだけ」の人には、ユーザーのメールと最終ログインを返さない（D-19）
- 「隠す」にした項目は、目次に出さず、URL を開いても中身を返さない
- ★役割ごとの判定は今のコードに無い（RECON-J・session.user.role は配線と表示のみ）。B-205 の判定関数が B-243（仮）の土台になる

### 5-3. 反映のタイミング（D-6）

- `src/lib/auth.ts` の jwt callback は今ログイン時（`if (user)`）だけ role を入れ、session callback は token から写すだけ（RECON-R6）
- 画面を開くたびに User の行（主キーで1行）で role・status を読み直す。停止・アーカイブの人はログイン画面に戻す
- ★読み直しを jwt / session のどちらに置くか、proxy（src/proxy.ts）から呼ばれる時に Prisma が動くかは、PR-2 のブリーフ前に測る

### 5-4. 扱わないもの

- EXTERNAL（B-172）・MASTER_ADMIN の判定（src 約90か所・B-242）・tenantType 軸の特権
