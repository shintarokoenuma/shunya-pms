# B-208 / B-250 追補 — 全字版フォントの名前が Regular と Bold で同じだった（2026-10-05）

- 対象: PR #188（ブランチ fix/b208-b250-pdf-font-hyphen @ 6628314）
- 発見: 2026-10-05 12:30 dev 確認 §3-2。WO-2026-0022 の PDF で、合計 ¥984,000 が「4,000」と出た（明細の金額は正しい）

## 1. 実物の PDF で分かったこと（12:41 にダウンロードした WO-2026-0022_20261005-124127.pdf を claude.ai 側で調べた）

- pdffonts: 埋め込みフォントは1つだけで、名前は ZDEHIM+NotoSansJP-Thin。Regular と Bold の2つが入るはずが1つになっている
- 画像にすると、ページの全文字が太字に見える（本来は細字の明細・備考も太字）。合計は「4,000」で「¥98」が描かれていない
- pdftotext では WO-2026-0022 が「WO-2 2 - 22」、瀬戸内ソーイングラボ が「瀬戸内ソーイ ラ」になる（0・6・ン・グ・ボ の対応が壊れている）

## 2. 原因

- fontTools の instantiateVariableFont を既定（updateFontNames=False）で使うと、名前テーブルが可変フォントの既定（Thin）のまま残る。400 と 700 で切り出した2本とも、PostScript 名（name ID 6）が NotoSansJP-Thin、ファミリ名が Noto Sans JP Thin になる（claude.ai 側で同じ可変フォント sha256 c2f3b4d4… から再現して確認）
- @react-pdf/pdfkit（4.x）の font() は、読み込んだフォントの PostScript 名で使い回しを判断する（「同じ名前のフォントがすでに PDF にあれば、それを使う」）。Bold と Regular が同じ名前なので、2本目は1本目のフォントに差し替えられる。文字の割り付け（どの字をどの番号で描くか）は元のフォントで決まっているため、描画で一部の字が抜けたり別の字になったりする
- Claude Code の試し（12:3x）で再現しなかったのは、取り出した文字列だけを見ていて、埋め込みフォントの数と画像を見ていなかったため（推定）

## 3. 直し方

- D-8 フォント2本を、同じ可変フォント（sha256 c2f3b4d4… を確認してから使う）から instantiateVariableFont(…, updateFontNames=True) で切り出し直す。名前は Regular が NotoSansJP-Regular / Noto Sans JP / Regular、Bold が NotoSansJP-Bold / Noto Sans JP / Bold になる（claude.ai 側で確認）。ファイル名・fonts.ts・family 名（NotoSansJP）は変えない
- D-9 確かめ方を「文字列」から「埋め込みフォントの名前」と「画像」に変える: 試しの PDF の埋め込みフォントが2つ（…+NotoSansJP-Regular と …+NotoSansJP-Bold）であること。差し替え前のフォントでは1つ（…+NotoSansJP-Thin）になることを先に見て、試し方が効いていることを確かめる（陽性対照）
- D-10 dev 確認は §3-1 から やり直す（§3-1 の合格は、全文字が太字の状態で見ていたため取り消す）

## 4. 学び（スキル shunya-pdf-document へ締めで追記する候補）

- フォントを差し替えたら、PDF の埋め込みフォントの名前と数を確かめる。Regular と Bold の PostScript 名が違うことをフォントファイルの時点でも確かめる（fontTools の name ID 6）
- 可変フォントから固定版を切り出すときは updateFontNames=True を付ける
- 帳票の確認は、取り出した文字列だけで合格にしない。画像にして目で見る
