## 2. なぜ「保持」と「照合」を分けたか（★本書の中核）

addendum §1 は「名寄せ基盤は B-171 / B-149 の共通の土台」と書いている。これは正しいが、共通なのは一部だけである。

| 機能 | B-171 専用オーダーページ（本命） | B-149 Excel 取込（移行期） |
|---|---|---|
| 先方品番・先方色名を**保持**する | 要る | 要る |
| それを画面に**表示**する | 要る | 要る |
| 先方コードの文字列を**照合**する | ★**要らない**（先方は一覧から選ぶ。突き合わせる文字列が発生しない） | 要る |
| 表記ゆれ（桁数・前ゼロ・英字大小・全角半角）の吸収 | ★**要らない** | 要る |
| 対応が付かない行の突き合わせ画面 | 原則発生しない | 要る |

**本命の B-171 が必要とするのは「保持と表示」だけである。** 照合は移行期の B-149 に固有の要求であり、そこへ寄せることで、本命ラインの手前で本命が使わない機能を作ることを避ける。

★実務の裏付け: 先方品番は1品番に1種だが、各社で表示の桁数と使用する英数字が異なる（§3-1）。この表記ゆれが問題になるのは、シート上の文字列を機械で当てにいく時だけである。

## 4. recon の実測（確定事実・調べ直し不要）

| 対象 | 実測 |

| 名寄せ専用モデル | **存在しない**（mapping / alias / xref いずれもゼロ） |

### 4-1. ★spec と実装の食い違い（設計時に注意）

color-master-spec §5 は仕入先の色を **Material.availableColors に [{colorNumber, supplierColorName}] として素材ごとに一度だけ持つ**と計画していたが、実装はそうなっていない。

- Material.availableColors は Json の [{name, code, hex}] のまま（未移行）
- 稼働している仕入色の器は **BomItemColorway**（BOM明細 × カラーウェイ）で、粒度は「素材ごとに一度」ではなく「BOM明細×カラーウェイごと」

★**②の設計は spec §5 の文面ではなく BomItemColorway の現物に倣った。** 文面に倣うと実装と噛み合わない。

## 5. データモデルの変更（確定）

### 5-1. 追加する列（1本だけ）

ProductColorway に先方色名を追加する。

- 列名: clientColorName
- 型: String? @map("client_color_name") @db.VarChar(100)
- nullable。未登録の配色があってよい（§6-2 の表示規則で吸収する）
- 長さ 100 は BomItemColorway.supplierColorName に揃えた
- migration: ADD COLUMN（nullable）＝**非破壊**

粒度が品番×配色である理由:

- 実データの先方色名に複合色名がある（addendum §0「BLACK×襟BLUEDENIM」）。これは Color の単色1つに対応せず、品番固有の配色である
- Product.clientId が必須 ＝ 品番は1クライアント専用 ＝ その配下の配色も1クライアント専用。クライアント別に分ける必要がない
- 仕入先方向（BomItemColorway）がカラーウェイ単位に外部名を持つ形と同型で、既存の実装思想と揃う

### 5-2. 追加しないもの（明示）

- 品番×クライアントの新テーブル … 作らない（Q1 により Product が既に対応表）
- クライアント色マスター／色辞書テーブル … 作らない（Q2）
- 先方の色コード列 … 作らない（Q3。必要になれば非破壊で追加できる）
- サイズの対応表 … 作らない（§8 で別 B番号）

### 5-3. コメントのみ変更

Sku.clientSkuCode に、未使用であることを schema コメントで明記する（Q5）。migration は不要。

★理由: 休眠列を無印で放置すると、次のセッションが「列があるから使われている」と誤認する。2026-09-07 に実際に起きかけた。

## 6. 画面（確定）

### 6-1. 入力（B-170 の範囲）

品番カルテのカラーウェイセクション（colorway-section.tsx）に、先方色名の入力欄を足す。

- 先方品番は Product の既存欄で入力する（新設不要）
- 品番は季ごとに新規発生する。**新品番の登録時に一度入れれば、以後は安定する**
- これにより名寄せが「取込のたびの作業」ではなく「品番登録時の作業」に前倒しされる

### 6-2. 表示規則（Q6・確定）

専用オーダーページ（B-171）では、**先方品番が未登録の品番を一覧に出さない。** 管理側に「先方品番が未入力の品番がある」旨の警告を出し、公開前に気づけるようにする。

★**派生規則（Claude の提案・要確認）**: 同じ規則を配色にも当てはめ、先方色名が未登録の配色は先方ページに出さないこととする。慎太郎さんが明示的に決めたのは品番についてのみであり、配色への適用は本書の派生である。異論があれば v1.1 で修正する。
