## 1. 決めたこと

- D-1（案2）: 下の対象セルを、縫製仕様書と同じ規則（D-10・D-12・D-13）で行を先に計算し、"\n" でつないで「折らせない」Text に渡す形にそろえる。react-pdf の hyphenationCallback に折り方を任せない
- D-2（対象セル）:
  - 発注書・作業発注書（order-document.tsx）: 明細の品名・品番の1段目・D/# の2段目・C#、上の対象品番ブロックの品名・品番
  - 見積書（quotation-document.tsx）・量産見積書（pe-quotation-document.tsx）: 明細の品名の欄（productLabel）・別枠の項目名（label）
  - 請求書（invoice-document.tsx）: 明細の伝票番号・品番・品名・摘要（description）・色/サイズ
  - 納品書（delivery-note-document.tsx）: 明細の品番・品名・色・サイズ、受注番号の列挙
  - 宛名・住所・振込先・ヘッダの伝票番号・金額の欄は対象外（今の形のまま）
- D-3（共通の部品）: 測る仕組みを帳票共通にする
  - Measurer を作る関数とフォントの読み込み（今の loadSewingSpecMeasurer と同じフォント）を、縫製仕様書専用でない名前で使えるようにする（縫製仕様書側の呼び出しは結果が変わらないこと）
  - 「セルの文字幅（pt）・フォントの大きさ・行間」を受けて行を返す入口を足す（textWidthOf の B4 余白に頼らない）
  - 各帳票の列幅は、その帳票のページ幅・ページ余白・列の %・セルの左右余白から pt で求める。求めた値は帳票ごとに定数として置き、PR 本文に表で書く
  - 描画は今の各帳票の見た目（列幅・フォントの大きさ・行間・揃え）を変えない。変わるのは折れる位置だけ
- D-4（欄より長い英数字のかたまり）: かたまり1つが欄の幅より長いときは、まず「-」「/」「_」の直後で折り、それでも入らない部分だけ文字の間で折る（B-267 の安全策を一段よくする）
  - 例: D/#「BORDER-2026-SPRING-01」が入らないときは「BORDER-2026-」「SPRING-01」のように折る
  - この変更は縫製仕様書にも効く（欄より長い英数字のかたまりがあるときだけ）。既存の sewing-spec-layout.test.ts はすべて通ること
- D-5（② ※ を避けた文言）: 慎太郎さんの条件どおり、戻す前に過去の記録を全部確かめる
  - 確かめる範囲: `git log -p -S'※' -- src/lib/pdf/ src/lib/` の全件、`git show 01e282c`、docs/specs/ の D-42 に触れている全文書（grep -rn 'D-42' docs/）
  - 同梱フォント（Regular・Bold の両方）に U+203B があることを fontTools の getBestCmap で確かめる（陽性対照として U+301C〜、陰性対照として cmap に無い字を1つ）
  - ※ を外して書き換えた文言が見つかったときだけ元に戻す。見つからなければ何も変えず、PR 本文に「戻すものは無し」と、確かめた commit と grep の結果を書く
  - ～→〜 の置き換え（pdfText）は残す（害がなく、DB の値に ～ が入っているため）
- D-6（③ コメント）: sewing-spec-data.ts:137-142 の pdfText のコメントを、全字版フォント（B-208）の今に合わせて書き直す。「サブセットに無い」「フォントの差し替えは別番号で扱う」を消し、「全字版では ～ も出るが、表示をそろえるため 〜 に置き換えている」旨にする。invoice-rows.ts の同名の pdfText のコメントも同じ状態なら合わせる
