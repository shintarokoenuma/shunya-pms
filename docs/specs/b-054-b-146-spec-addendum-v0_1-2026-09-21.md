| D-22 | ★型紙の版番号（version / versionNumber）は自動採番（その型番の最大 versionNumber + 1、version は "v" + 番号）。**論理削除済みの行も数える**ため、削除すると番号が飛ぶ（v2 を消すと次は v3）。@@unique([modelCodeId, version]) が deletedAt を見ないための必然であり、**番号は再利用しない**。画面には出さず、主表示は受領日（D-12） | 慎太郎さん 2026-09-21「追認する」／実測 pattern-versions.ts:159-166・dev の3行（M-018） |

### D-23 の根拠（署名URL方式を採らない理由）

- react-pdf 4.5.1 の型定義（@react-pdf/types の image.d.ts）で、SourceDataBuffer の format は 'png' と 'jpg' のみ。WebP は描けない
- 絵型の原本は変換せずそのまま保存している（product-sketches.ts → uploadProductSketch に file.type / ext を渡す）。許可 MIME は png / jpeg / webp
- dev で絵型を持つ唯一の品番（AOI-26SS-M-TS-001）の原本3枚はすべて webp
- react-pdf は EXIF の向きを見ない。B-204 で直したのはサムネ生成だけで、原本は EXIF 付きのまま
- JPEG は透過を持てず、sharp の既定では透過部分が黒になる

## 3. PR-4 への申し送り

- 部品: import { loadSketchForPdf } from "@/lib/pdf/sketch-image"（呼び出し元はまだ無い）。原本の読み出しは gcs.ts の downloadToBuffer
- 用紙は D-24 の寸法で指定する。書き方は 3d6f40b の src/lib/pdf/sketch-probe-document.tsx が参考になる
- フォント: fonts.ts の registerPdfFonts() と PDF_FONT_FAMILY（order-document.tsx と同じ）
- ルート: params は Promise で受ける。Response は new Uint8Array(buffer) ＋ Cache-Control: no-store（work-orders/[id]/pdf/route.ts が手本）
- ★未ログインの要求は src/proxy.ts が /login へ **307** で転送する（401 ではない）。ルート内の auth() も残す
- 画像の読み出しは直列。枚数が多くて遅ければ Promise.all にする
- dev 確認では透過 PNG とスマホ縦撮り JPEG を1枚ずつ足して見る
- 型紙の日付: 宛先 WO の patternVersionId があればその行、無ければ型番の最新 receivedAt（実装ブリーフのとおり）。★SP / WO への型紙の紐付け UI は未実装なので、当面は常に型番の最新行になる
- 型番の pattern_number は既存分がほぼ空（PDF の帯で空のときの表示は PR-4 で決める）
