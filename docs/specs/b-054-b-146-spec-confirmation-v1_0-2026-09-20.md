## 4. 仕組みの変更（すべて非破壊・PR-1 で適用済み）

### 4-1. パターン番号 — ModelCode に列を1本

    model ModelCode {
      // ... 既存 ...
      // B-146: 型紙そのものに振った番号（例 16sy-082）。2nd・グレーディング・量産・リピートで不変（M-015）
      patternNumber String? @map("pattern_number") @db.VarChar(50)
    }

- 置き場所を ModelCode にする理由: リピートでも同じ番号を使う（M-015 確定3）。ModelCode はリピート系譜の単位で products[] を持つ。Product に置くとリピートのたびに写す必要がある。
- 一意制約は付けない。
- D-17 を受けた入力の既定: 品番から自動生成される型番には、パターンNO の初期値として社内品番を入れる（実装済み）。先方支給のパターンや、品番より先に番号が付いた過去分は、実際の番号に書き換える。

### 4-2. 職出し予定日 — WorkOrder に列を1本

    model WorkOrder {
      // ... 既存 ...
      // B-054: 職出し予定日（工場ごと＝WO ごと）。実績は productionStartedAt
      plannedStartDate DateTime? @map("planned_start_date") @db.Date
    }

- 列名は SampleProduction.plannedStartDate と揃える。

### 4-3. 検品所 — FactoryType に値を1つ

    enum FactoryType {
      // ... 既存12値 ...
      INSPECTION // 検品（検品所）
    }

- ALTER TYPE "FactoryType" ADD VALUE 'INSPECTION'。既存行に影響なし。
- PostgreSQL の制約で ADD VALUE は同一トランザクション内で使えないため、**migration ファイルを分けた**（20260921000000 と 20260921000100）。
- 工場マスターの選択肢・ラベルは src/app/(app)/factories/_components/labels.ts に追加済み（13件）。

### 4-4. 運用
- prisma migrate dev は使わない。migrate diff のドライラン → dev に db push → 手書き migration → 一致検証 → 本番は Railway の migrate deploy。
- migrate reset・--accept-data-loss は使わない。

## 5. B-146 の最小範囲（今回起こす部分）

### 5-1. 型紙の記録（PatternVersion を起こす）— PR-2 で実装
- 品番カルテから、型番（ModelCode）に対して**型紙の受領を1行ずつ記録**する。
  - 入力: 受領日（receivedAt・必須）／種別（workType: 新規・修正・グレーディング追加・グレーディング修正・別モデルからコピー）／グレーディングの有無とサイズ（hasGrading・gradingSizes）／修正内容（revisionNotes）／データの置き場所（driveFileUrl）／パタンナー（contractorId）
  - version と versionNumber は必須列のため**自動採番**（v1, v2, …）。画面には出さない。主表示は日付（D-12）。
- パターン番号（§4-1）は型番の編集欄に1つ（PR-1 で実装済み）。
- Specification / DesignVersion は今回起こさない（B-146 の残り・B-147 はそのまま）。

### 5-2. 「どの型紙で作ったか」（後続）
- サンプル製作（SP）と WO で patternVersionId を選べるようにする（既定は、その時点で最新の受領日の行）。
- PDF の品番の帯の「型紙 YYYY-MM-DD 種別」は、**宛先の WO に紐づく型紙**を出す。WO に紐づきが無ければ型番の最新行を出す。

### 5-3. 画像で当面しのぐもの
- サイズ表（2枚目）と加工指示の中身（3枚目）は、器ができるまで Product.sketchImages に上げた画像を載せる。寸法の Excel 取込は B-056、メール取込は B-206 の範囲。
- 各ページにどの絵型・画像を載せるかは、**PDF を出すときに選ぶ**（既定は caption・sortOrder から推定）。割り当てを保存する列は作らない。
