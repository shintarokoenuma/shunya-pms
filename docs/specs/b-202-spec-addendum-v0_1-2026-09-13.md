## 2. 各確定の根拠

### Q2 絵型タブ
- `Product.sketchImages` は `{gcsPath, thumbGcsPath, caption?, sortOrder}` の配列。面を表す属性は無い
- タブの並び順は `sortOrder`、タブ名は `caption`。★`caption` が空のときのタブ名は実装ブリーフで確定（暫定は連番）
- ★既存データの `caption` の使われ方は未測定。実装ブリーフの前に dev を read-only で見る

### Q3 進行
- 慎太郎さん「aでいいともう。」＝並行・対象外が画面から読めないのが問題。並び順を案件ごとに変える仕組みは作らない
- `ProgressTask.sortOrder` は列としてあるが、ユーザーが並べ替える action は存在しない（実測）

### Q4 表示スイッチ
- `CompanySetting`（`companyId @unique`）は **src 実使用ゼロの休眠**だが `uiPreferences Json?` が既存 → **migration なし**
- ★休眠のため「行が無ければ作る」処理が要る
- `SystemConfiguration` はグローバル粒度で不採用。`NotificationPreference` は通知専用で不採用
- ★**ユーザー単位の表示設定の器は存在しない**（人ごとにするならテーブル新設が必要だった）
- 名前空間は段階3（B-203）へ移せる形にする（例 `uiPreferences.productKarte.memo.*`）

### Q5 引き出し
- 下開き。★条件: ①同時に開くのは1つ ②中身は引き出しの内側でスクロール ③横長の表は引き出し内で横スクロール
- 根拠: BOM 1,285行・概算量産見積 2,064行（RECON-L）

### Q7 A4 印刷（→ B-054 へ）
慎太郎さん原文（2026-09-13）:
> PDFで送る資料は絵型がメインになるので、待った置く同じものは難しいかもしれない。
> 細かい仕様など、ある為、絵型に書き込みなどが見えるようにしたい。品番、パターンなんばー、納期など重要な内容が入ったヘッダーだけ共通で、絵型や写真だけ追加したい。
> また、７面全てを必要としない場合が多いので、PDFに落とす際は、ページのチェックをしたい。

- PDF は絵型が主役。画面と同一紙面にしない。共通はヘッダーだけ（品番・パターン番号＝型紙の版・納期）
- ★BACKLOG の B-054 の定義文は「縫製仕様書の帳票出力（実Excel構造が原本・最終フェーズ）」。
  「品番サマリー1枚 PDF」は b-094 spec §6 側の呼び方（段1）で、同じ番号の別の言い方（2026-09-13 実測で確認）
- ★出力ページのチェックは B-203 と同型の機能。段階3で同じ仕組みに載せるかを判断する

### Q10 絵型の書き込み
- 現場は既に注記入りの絵型を画像で上げている。PDF で大きく出せばよい
- ★注記の器（座標つきアノテーション）は作らない。★サムネ（`thumbGcsPath`）ではなく原本（`gcsPath`）を使う。解像度は未測定

### Q11 パターン番号（→ B-146 へ）
- 慎太郎さんの確定: PDF ヘッダの「パターンなんばー」は**型紙の版（v1 / v2 / v3）**
- `PatternVersion` は **src 実使用ゼロの完全休眠**。器は完備（`modelCodeId` / `version` / `baseVersionId` / `workOrderId` /
  Drive ファイル / `contractorId` / `workType` / `revisionNotes` / `hasGrading` / `storageLocation` / `@@unique([modelCodeId, version])`）
- `ModelCode`（型番 M-MK-0001）は稼働中（src 16ヒット）。`TextilePattern.patternNumber` は**生地の柄番号**で別物
- ★**新規起票しない。** BACKLOG の重複確認（2026-09-13）で **B-146 が受けている**ことを確認した
  （B-146 の定義文に「PatternVersion は…完備だが呼び出しがコード上に無い」と明記されていた）。
  関連: B-025（型・版・品番の3層）／B-023（版類の在庫）／B-056（パターンデータ取込）／B-022（パタンナー開放）
