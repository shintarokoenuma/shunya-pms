## 2. 確定・訂正

### D-15 レイアウトのドラッグ配置は採用しない

慎太郎さんの問い（2026-09-15「ドラックで動かせるようにしたほうがいいのかな？」）への結論。**採用しない。**

1. 配置の保存先が要る（会社か個人か・端末ごとか・画面幅ごとか）。決めた瞬間に `CompanySetting` / 新規テーブルが要り、B-202 の「migration ゼロ」（D-9）を失う
2. 案C の目的（工場に渡せる**共通の1枚**・B-054 の1枚PDFと同じ紙面）と相反する。人ごとに紙面が変わると「あの欄はどこ」が毎回起きる
3. 見づらさの原因は配置ではなく**カラム内の中身の高さ**だった。動かせても短くならない

★代替は **B-203（表示項目の出し分け）**。位置ではなく表示/非表示なら保存先が単純で、紙面の一貫性も壊れない。

### D-16 進行は「1画面＝要約チップ／編集＝共有パネル」に分ける

- 1画面（右カラム）には `production-progress-chips.tsx`（Server Component・状態なし・追加クエリ0）を置く
- チップ名 = `PROGRESS_TASK_TYPE_LABELS[taskType]`。`PROCESSING` は `processingTypeName`
- 注記は実在列のみ: `DONE` かつ `checkedAt` → `M/D` ／ `SKIPPED` → `対象外`（取り消し線）／ `isReceived` → `工場入荷` ／ それ以外は `notes` の先頭14字
- 色は既存 `PROGRESS_TASK_STATUS_BADGE_VARIANT` を流用（新しい色を定義しない）
- ★並びは `sortOrder` のまま。**矢印・番号・棒グラフなど順序を暗示する装飾は付けない**（v1.0 D-4）
- 編集（`ProductionProgressChecklist`・364行・**無変更**）とステータス履歴は、ボタンバーの**先頭グループ `prog`「進行（編集）」**へ移設

★**ボタンバーは6グループではなく7グループになった**（v0.3 D-13 の6は例示であって上限ではない）。

### D-17 絵型は全幅1段の帯・1画面は2カラム（★D-12 からの暫定変更）

慎太郎さんの指摘（2026-09-15「まだ、絵型とか全く見えないね。絵型を一段いっぱいに使ったらどう？」）。

- D-12 の3カラム（左＝絵型 216px）では、既存 `SketchSection`（複数枚サムネ＋操作ボタン）が収まらず、絵型が幅70px の短冊3本に潰れていた（実機で確認）
- **絵型をヘッダ直下の全幅1段へ**。高さ `h-60`（240px）固定・`object-contain`・はみ出しは横スクロール（枚数が増えても1画面の縦は伸びない）
- 帯のサムネは `thumbUrl`（長辺400px WebP）。原本は拡大時のみ読む
- 残り4ブロックは**2カラム**（左＝品番・分類＋縫製指示 / 右＝カラー×数量＋進行）。★4ブロックを3カラムに割ると右だけ1,000px になり高さが揃わない
- ★**これは暫定である。** PR-2 で絵型を「1枚＝1タブ」にすれば1枚だけの表示になり、D-12 の左カラム 216px に戻せる可能性がある。**PR-2 で再判断する**

### D-18 絵型はクリックで原寸拡大する（★v0.3 の引用漏れ）

モック案C の原文に明記されていた。

    <div class="sketchbox" id="sketch-view">前身頃<br><span style="font-size:10px">クリックで拡大</span></div>

- v0.3 §1 はレイアウト（CSS・HTML構造）だけを引用し、**モック内の文言を引用しなかった**ため落ちた
- 実装: サムネを `DialogTrigger` で包み、`DialogContent` に原本（`url`）を `max-h-[80vh] object-contain` で表示。`DialogTitle` は `caption ?? 絵型 N`
- `getProductSketchUrls` が `url`（原本）/ `thumbUrl`（サムネ）を**両方署名済みで返す**ため追加クエリ0
- ★v0.1 Q10「書き込み済み画像を大きく出す」は、本 D-18 で実装された

### D-19 型番・担当者は getProduct の manual join で解決する（Q6r の確定）

- **Q6r 確定: 担当者は表示する。**ヘッダ右端（シーズン／クライアント／想定数量／希望納期の列）に `担当者 ○○`（★実装のラベルは `担当者`）

| # | 日付 | 落としたもの | 結果 |

★**共通の原因**: モックの **CSS と HTML 構造だけを引用し、モック内の文言・注記を引用しなかった。** v0.3 §6 のルール2「レイアウト・UI の決定は原文を引用してから要約する」は、レイアウトに限定されていたため文言を拾えなかった。

### 再発防止ルールの追加（v0.3 §6 のルール2 を差し替える）

> **2r. モックを引用するときは、CSS・HTML 構造だけでなく、モック内に書かれた文言・注記・メトリクス表示もすべて引用する。**
> 「クリックで拡大」「0 スクロール」「— 直列に並べない」のような**画面に書かれた短い文字列が仕様である**ことが多い。
> レイアウトの数値だけを写して文言を落とすと、実装後に必ず追加 commit が発生する。
