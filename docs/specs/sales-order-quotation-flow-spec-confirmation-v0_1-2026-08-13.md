## 0. 確定した業務フロー

    概算見積（QE-1R / RoughEstimate）  仕様・素材確定前・交渉用
        ↓ OK
    サンプル作成（SampleProduction）
        ↓ 確定サンプル指定（1品番1点）
    量産見積（PE / ProductionEstimate） サンプル実績ベース・想定数量
        ↓ 展示会・受注期間
    確定見積（QE-2 / Quotation）       ★先方の確定数量で作り直す
        ↓ ★承諾 / 失注の分岐がある
    受注確定（SO / SalesOrder 発番）
        ↓
    量産発注（PO / WO）

## 1. 確定見積（QE-2）が必要な理由 — 数量変動

**慎太郎さん原文（2026-08-13）**:
> 展示会ベースのクライアントは最終の量産オーダー数次第で、見積もり数量が
> 上下するので、先方指定の量産数量で作成した場合、見積もりが変わるので、
> 確定見積もりが必要になる。

> オーダー数量を元に単価が変動します。100枚が60枚になれば、生地代や工賃が
> 変わるので。

### 1-1. 数量変動で何が動くか

| 変動要因 | 内容 |
|---|---|
| 生地の取り切り（ROLL） | 反単位で買うため、60枚でも必要反数が100枚時と同じなら1枚あたりの生地代が跳ね上がる（`qe-1 v1.0` §4 の「端数で1反増える」がそのまま効く） |
| 工賃の数量単価 | 工場の縫製工賃に数量の段がある（`QuotationMoqTier` 相当の実務） |
| 初期費用 | 総額は不変。ただし**1枚原価には混ぜない別枠**（絶対防衛線）のため単価は動かない |

### 1-2. ★再計算の方式（R-1 確定・案A）

- **単価は人が手打ちで入れ直す。**
- **取り切り（反数）の再計算のみ自動で行う。**

根拠: `QE-1R v0.1` §5-2「最終的な提示見積金額・（将来の）納品金額は人が手打ちで
整える」を確定見積にも適用する。工場から60枚時の見積を取り直して打ち込む、という
現在の運用がそのまま乗る。

反数計算は `src/lib/calc/production-cost.ts` に純関数として実在（`production-axis v1.0`
§1-4）。数量を差し替えれば再計算できる。人が電卓を叩く部分ではない。

★**帰結: MOQ 階段単価（`QuotationMoqTier`）を実装しなくてよい。**
B-153 の定義に「単価手打ち方式の採用により階段は実装しない」旨の注記が必要（未実施）。

## 2. 確定見積 ≠ 受注確定（R-2 確定）

**慎太郎さん原文（2026-08-13）**:
> ほとんど、確定するが、あまりにも数量が少ないなどで、金額が極端に変動した
> 場合、オーダーが来ない場合もある。

### 2-1. 設計上の帰結

- **確定見積の発行を SO 発番の契機にしてはならない。**
  そう設計すると、失注した確定見積が SO として残り、量産発注生成の対象に入る。
- SO は**先方の意思表示があって初めて発生**する。

### 2-2. ★この失注は原設計が想定した失注と性質が違う

サンプルを作り、展示会に出し、確定見積まで出したうえで流れる失注である。
**工数もサンプル代も既に発生している。**

原設計（13ステップ）の 13「クロージング・分析 → 粗利・受注率・失注理由分析」が
拾うべきなのは、まさにこのパターン。引き合い段階の失注とは分析上の意味が違う。

`SalesOrderStatus` enum の実在値は未確認。失注の表現方法は B-148 の設計時に
live schema を読んでから決める。

## 3. ★依存関係（R-3 確定）— 起票時には見えていなかった

**B-143（確定見積 QE-2）は B-148（受注 SO）に依存する。**

理由: 確定見積の分母は「先方指定の量産数量」＝受注数量である。受注が無い状態で
確定見積を作ると、数量の出どころが手入力になり、量産発注生成で起きているのと
同じこと（入力値がどこにも残らない）を繰り返す。

原設計 §2.6「量産発注は受注合計 + 歩留まり率（標準5%）で自動計算」の
「受注合計」が、確定見積の分母でもある。

### 3-1. 着手順（確定）

| 順 | B番号 | 内容 |
|---|---|---|
| 1 | B-148 | 受注（SO）本実装 ← 数量の正を立てる |
| 2 | B-143 | 確定見積 QE-2（B-144 を設計内で扱う） |
| 3 | B-149 | 流入経路（1系統のみ。4系統揃える必要なし） |
| 4 | B-146 → B-147 | 仕様書（三位一体）→ Product Json 統合 |
| 後回し | B-151 / B-152 / B-153 | 中越言語 / 色列FK化 / QE-3+ |

★Phase 戦略（1B見積 → 1D受注）および MVP実装計画書 §10.1（最優先1位＝見積もり
エンジン）とは順序が逆に見えるが、これは **QE-2 が見積系でありながら受注の下流に
ある**という位置づけの特殊性による。原設計 M4「受注MVP」の完了基準が
「受注登録・**量産発注連動**が動く」であり、確定見積は M4 の中に含まれると読む。

## 4. 流入経路（R-4 確定）

`sku-design v1.0` §2-2 の原文:
> 出口を **SalesOrder に一本化**し、入力経路（saagara-v2 連携 / CSV・Excel・メール
> 取り込み / 受注ページ先方入力 / カルテ手入力）はすべて SalesOrder を作る手段として
> 後付けする。SKU 別「受注数」の正は常に SalesOrder。

- **B-148（出口）の完了が B-149（流入経路）の前提。** 出口が無い状態で取り込み口を
  作らない。
- 4系統は互いに独立。**1系統作れば受注は回り始める。** 4つ揃える必要はない。
