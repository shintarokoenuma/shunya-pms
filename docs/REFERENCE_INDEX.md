### 中身（shunya-pms と違う点）

- 案件番号が `JSD-2609-xxx`、顧客が「チーム」（サンライズBC様・東雲メッツ様 等）
- 商材が野球ユニフォーム・キャップ。工程系統が **刺繍** と **昇華** の2本立てで並びが異なる
- 外注先の週キャパで納期が決まる前提（工程時間の足し算では決まらない、と明記されている）
- **全額前金制・入金確認後に手配開始**。仮引当は見積有効期限で自動解放、締切は月末27日
- 在庫は **売り減らし運用**。廃盤でも「今回の所要量 ≦ 引当可能残」なら売る
- 現物に QR を貼り、現場スタッフのスマホで「完了」と「数量」だけ入力する

shunya-pms は MARKA 等向けの OEM で、前金制でも QR 現場端末でもなく、在庫の売り減らし運用でもない。
**業務モデルが根本から異なる。**

### ★使ってよい範囲（これだけ）

**状態表現の作法**のみ。B-091（ピクトグラム）・B-188（セマンティックカラー）の参考にする。

- 状態を **色ではなく形** で区別している
  - 未着手＝白丸 ／ 進行中＝半分塗り ／ 完了＝黒丸 ／ 停止・要対応＝二重丸に「!」 ／ 対象外＝点線
- 遅延行は **行の左端に太い罫1本＋行背景** で表す（色に依存しない）
- 凡例を表の直下に必ず置いている
- ★全体が **彩度ゼロのグレースケールだけで成立している**。
  「色だけに意味を載せない」（色覚多様性）の要件を満たす実装例として有効

### 使ってはいけない範囲

業務モデル・画面構成・KPI の選び方・工程定義・引当ロジック・納期の決まり方。

★**B-090（品番カルテ一覧の2段表示）の設計軸の根拠にしない。**
2026-09-05 時点の引き継ぎメモ ⑤ と `docs/BACKLOG_EVIDENCE.md` の B-090 欄が本資料を参考として挙げているが、

## 点検記録

### 2026-09-05 — B-101/B-096 が別案件の業務前提を継いでいないかの点検

きっかけ: 上記 HTML が `docs/specs/b-101-b-096-production-progress-spec-confirmation-v0_1-2026-08-02.md:10`
で「一次資料」として引用されていると判明したため。

**結論: 混入なし。** 根拠は3点。

1. 別案件に固有の業務語彙（前金・入金確認後・週キャパ・売り減らし・廃盤・仮引当・引当可能残・
   昇華・背番号・キャップ型・JSD-）が `docs/specs/` / `src/` / `prisma/schema.prisma` に **0件**。
   ★「刺繍（EMBROIDERY）」だけはヒットするが、shunya 自身の加工種別で 2026-05〜06 から存在し、
   本 HTML（2026-08-01）より前。別案件由来ではない。
2. **確定版 v1.0（2026-08-03）は一次資料・叩き台に一切言及していない。** 引用しているのは v0.1 ドラフトのみで、
   実装着手は v1.0 から。実装の根拠は本 HTML に依っていない。
3. 実装された `PRODUCTION_TASK_TEMPLATE`（11種）は
   FABRIC → TRIM → GRADING → CUTTING → SEWING → INSPECTION → FINISHING → PACKING →
   SHIPPING → DELIVERY → INVOICE ＝ アパレル OEM の標準工程。
   別案件の特徴工程（昇華・転写・背番号・プレス機）は 0件。

★同じ疑いが再燃したら本節を読み、再点検を省く。
